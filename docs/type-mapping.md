# Oracle → PostgreSQL type & construct mapping

Applied consistently across the HR, CO and SH ports.

## Data types

| Oracle | PostgreSQL | Notes |
|---|---|---|
| `NUMBER(p,s)` (money/decimal) | `numeric(p,s)` | e.g. prices, `amount_sold` |
| `NUMBER(1..9)` scale 0, `NUMBER` (surrogate ids) | `integer` | id / key / count columns |
| `NUMBER(10)` | `bigint` | 10 digits can exceed `int4` range |
| `NUMBER` (unbounded, non-id) | `numeric` | e.g. `cust_credit_limit` |
| `VARCHAR2(n [CHAR])` | `varchar(n)` | `CHAR` length semantics dropped |
| `CHAR(n)` | `char(n)` | |
| `DATE` | `date` | Oracle sample data is date-only |
| `TIMESTAMP` | `timestamp` | |
| `BLOB` holding JSON (`co.products.product_details`) | `jsonb` | `CHECK (... is json)` dropped; `jsonb` enforces validity |
| `BLOB` (binary) | `bytea` | `co.stores.logo`, `co.products.product_image` (no data loaded) |

## Constructs

| Oracle | PostgreSQL |
|---|---|
| `'' ` (empty string = NULL) | `NULL` — Postgres keeps `''` distinct from NULL, and `''` breaks numeric/date/NOT-NULL columns, so empty-string *values* are converted to `NULL` |
| `GENERATED BY DEFAULT ON NULL AS IDENTITY` | `GENERATED BY DEFAULT AS IDENTITY` (`ON NULL` dropped); sequences advanced past loaded ids (`05_identity_sync.sql`) |
| `CREATE SEQUENCE ... NOCACHE NOCYCLE` | `CREATE SEQUENCE ... CACHE 1 NO CYCLE` |
| `ORGANIZATION INDEX` (IOT) | plain table + `PRIMARY KEY` |
| `PARTITION BY RANGE (col) (... VALUES LESS THAN TO_DATE(...))` | `PARTITION BY RANGE (col)` + `CREATE TABLE ... PARTITION OF ... FOR VALUES FROM (..) TO (..)`; `COMPRESS` dropped; a `DEFAULT` partition added |
| `UTL_RAW.CAST_TO_RAW('<json>')` | the JSON string literal, inserted into a `jsonb` column |
| `TO_TIMESTAMP('..','..FF')` | `to_timestamp('..','..US')`, fractional seconds truncated to microseconds |
| `TO_DATE(str, fmt)` | `to_date(str, fmt)` — same built-in in Postgres |
| `LISTAGG(x, sep) WITHIN GROUP (ORDER BY y) [ON OVERFLOW ...]` | `string_agg(x, sep ORDER BY y)` |
| `GROUPING_ID(a,b)` + `GROUP BY GROUPING SETS (...)` | `GROUPING(a,b)` + `GROUP BY GROUPING SETS (...)` |
| `JSON_TABLE(col, '$' COLUMNS(NESTED PATH '$.arr[*]' ...))` | `CROSS JOIN LATERAL jsonb_array_elements(col->'arr')` + `->>` extraction |
| `CREATE VIEW ... WITH READ ONLY` | `CREATE VIEW ...` (views are read-only by default) |
| `CREATE MATERIALIZED VIEW ... ENABLE QUERY REWRITE` | `CREATE MATERIALIZED VIEW ...` (rewrite clause dropped; `REFRESH` to update) |
| PL/SQL procedure + row trigger (`update_job_history`) | PL/pgSQL function + `CREATE TRIGGER ... EXECUTE FUNCTION` |
| Oracle object types, `VARRAY`, nested tables, `XMLTYPE`, `ORDSYS` (OE, PM schemas) | excluded — no PostgreSQL equivalent (see conversion-notes) |

## Load ordering

Data is loaded **before** foreign keys and secondary indexes are created. This avoids
insert-ordering problems (including HR's cyclic `employees ⇄ departments` reference) and
speeds up the bulk load. Primary keys, unique and check constraints are created up front.
